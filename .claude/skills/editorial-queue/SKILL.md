# Editorial queue

Read and obey `../seo-contract/SKILL.md` before starting. No push, merge, publication or scheduling is allowed.

Adapted from the described pattern-drip workflow as an editorial checklist, without daily production or publication automation. Read-only by default; drafts may be returned in the session or an owner-designated location outside the repository.

1. Read candidate briefs, original author material, existing URLs and outstanding review findings. Do not infer that a brief or page has been approved or published.
2. List a small queue with topic, reader value, original contribution, target URL, brief status, evidence gaps, dependencies and next action. Use these states: **material exists**, **missing data**, **draft**, **ready for review**. Distinguish content readiness from publication approval.
3. Prioritize one next item by material readiness and value, explaining the choice. Recommend an existing-page improvement when it is more useful than a new page. If no candidate has sufficient original material, say so and list the missing input.
4. Reuse technical checklists and templates, never fabricate unique value by swapping keywords or locations. Do not generate a batch of pages, set a daily quota, assign automatic publication dates or install cron/workflow/routine jobs.
5. For the next candidate, list remaining source/fact checks and the files/checks ship-page would need. Keep private notes and unpublished drafts out of the tracked and served tree.

End **queue ready for owner review; site diff: none**. Only an owner-reviewed brief may move to scoped local edits through ship-page.
