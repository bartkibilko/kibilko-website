# Page brief

Read and obey `../seo-contract/SKILL.md` before starting. No push, merge, publication or scheduling is allowed.

## Inputs

A topic or reader question, author-supplied material, current repository and optional owner-supplied Search Console export or public references. If a required author fact is missing, mark it for confirmation and prepare the rest without inventing it.

## Procedure

1. Build the current URL map from public HTML, sitemap, feed and internal links. Read relevant pages and `_templates/post/index.html`. Record overlapping intent and unique existing material.
2. Identify the audience, question and original contribution. Separate name/profile searches, informational topics and possible collaboration intent. Multiple query variants can belong to one page; multiple URLs alone do not prove harmful competition. Name the single original element this page offers that comparable published pages do not (author data, a diagram from real work, a worked example, a tool, a measured result). If none can be named from author material, the decision is **no change** or **missing data**, not a new page.
3. Choose **update existing**, **new page**, **no change**, or **missing data**, explaining the evidence and alternatives. An absent analytics row alone does not justify a new page. In no-data mode, base the decision on content overlap and label demand as unmeasured.
4. Propose a plain title, description, outline and useful contextual links. Plan canonical, language, social card and structured data only where supported by visible facts. Do not copy another author's text or illustration. Avoid fabricated dates, credentials, ratings and measurements. Plan inbound contextual links from every existing page on a close topic (in body text, not navigation only); target at least three where that many related pages exist, and list each source page and anchor.
5. Enumerate every affected publication file: page, assets, relevant template, blog listing, sitemap and feed. Check whether each actually needs a change rather than editing all by default. Define acceptance criteria, content to preserve and any URL/redirect decision requiring review.

## Review result

Return the decision and target URL; reader need and original material; `original element:`; proposed metadata/outline; source references and dates; author facts awaiting confirmation; planned files/internal links; preservation checklist; and acceptance checks. Explicitly state **no-data mode** when applicable. End with **brief ready for owner review; site diff: none**. Pass only the reviewed scope to ship-page; do not edit public files here.
